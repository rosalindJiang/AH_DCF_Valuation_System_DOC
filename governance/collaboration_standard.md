# 协作规范

## 1. 协作目标

本项目虽为设计方案，但按照真实工程项目管理方式组织，以体现团队协作、版本控制和质量保证能力。

## 2. 角色分工

| 角色 | 职责 |
|---|---|
| Project Owner | 明确业务目标、确认最终方案 |
| Data Engineer | 设计数据采集、清洗、入库流程 |
| Quant Researcher | 设计 DCF 估值方法与参数假设 |
| Backend Engineer | 设计系统模块、任务调度和接口 |
| Reviewer | 检查文档完整性、逻辑一致性和可维护性 |

## 3. 工作流程

```text
提出需求 Issue
   ↓
建立功能分支
   ↓
修改设计文档或配置模板
   ↓
提交 Pull Request
   ↓
根据 Review Checklist 检查
   ↓
合并到 main 分支
   ↓
更新版本记录
```

## 4. 文档规范

- 所有核心设计文档使用 Markdown；
- 文件名使用小写英文和下划线；
- 每篇文档开头说明目的；
- 表格字段需要明确含义；
- 公式需要配套解释；
- 不在文档中存放真实密钥和账号信息。

## 5. 质量要求

每次提交前需要检查：

- 是否影响 README 总览；
- 是否与数据契约冲突；
- 是否需要更新配置模板；
- 是否改变 DCF 计算假设；
- 是否需要补充异常处理逻辑。
