# 02 系统架构设计

## 1. 总体架构

系统采用分层架构设计，自上而下分为：

1. 用户与配置层；
2. 调度与任务层；
3. 数据采集层；
4. 数据处理层；
5. 估值计算层；
6. 数据存储层；
7. 结果服务层；
8. 监控与质量控制层。

```text
用户 / 投研人员 / 量化研究员
          ↓
配置管理层：股票池、数据源、估值参数、运行模式
          ↓
任务调度层：日度、周度、月度、手动批量任务
          ↓
数据采集层：行情、财报、基础信息、宏观参数
          ↓
数据处理层：清洗、对齐、标准化、异常检查
          ↓
估值计算层：FCFF 预测、WACC、终端价值、股权价值
          ↓
数据存储层：原始数据、中间结果、最终估值结果
          ↓
结果服务层：估值表、排序表、报告、下游接口
          ↓
监控层：日志、异常、数据质量、运行状态
```

## 2. 核心模块设计

### 2.1 配置管理模块

负责读取并管理：

- 运行市场：A 股、H 股、A+H；
- 股票范围：全市场、行业、白名单、样本股票；
- 数据源优先级；
- DCF 预测参数；
- WACC 参数；
- 终端增长率参数；
- 数据库连接信息；
- 调度频率。

该模块使系统不需要修改业务逻辑即可调整运行范围和估值假设。

### 2.2 数据采集模块

负责从外部数据源获取数据。设计上不绑定单一接口，而是采用适配器模式：

```text
DataSourceAdapter
├── BaostockAdapter
├── AkShareAdapter
├── TushareAdapter
├── YahooFinanceAdapter
└── ManualUploadAdapter
```

每个适配器输出统一字段格式，供后续清洗模块处理。

### 2.3 数据清洗模块

负责处理跨市场数据差异，包括：

- A 股代码格式如 `600000.SH`；
- H 股代码格式如 `0700.HK`；
- 财务报表币种与行情币种统一；
- 年报、半年报、季报数据频率统一；
- 缺失值与异常值标记；
- 财务字段口径标准化。

### 2.4 财务预测模块

负责根据历史财务数据生成预测期 FCFF。

主要预测对象包括：

- 营业收入；
- EBIT；
- 所得税；
- 折旧摊销；
- 资本开支；
- 净营运资本变动；
- 自由现金流。

预测方式支持：

- 历史 CAGR；
- 行业中位数；
- 人工假设；
- 保守、中性、乐观三情景。

### 2.5 DCF 估值模块

负责计算：

- 显式预测期现金流现值；
- 终端价值；
- 企业价值；
- 股权价值；
- 每股内在价值；
- 估值偏离度；
- 敏感性分析结果。

### 2.6 数据存储模块

数据库建议采用 SQLite、PostgreSQL 或 MySQL。考试设计方案中推荐 SQLite 作为最小可运行系统的本地数据库，后续可扩展到 PostgreSQL。

存储内容包括：

- 股票基础信息；
- 行情数据；
- 财务数据；
- 估值假设；
- 估值中间结果；
- 最终估值结果；
- 数据质量报告；
- 运行日志。

### 2.7 监控与质量控制模块

负责：

- 接口调用失败记录；
- 数据缺失率统计；
- 异常估值结果识别；
- WACC 小于终端增长率的错误检查；
- 内在价值极端值检查；
- 批量任务运行状态记录。

## 3. 架构设计优势

| 设计点 | 优势 |
|---|---|
| 分层架构 | 模块职责清晰，便于维护 |
| 配置驱动 | 股票范围和估值假设可灵活调整 |
| 数据源适配器 | 后续可接入更多数据源 |
| 数据契约 | 明确字段口径，降低协作成本 |
| 中间结果入库 | 估值过程可追溯 |
| 质量控制模块 | 降低批量估值异常风险 |
| 协作规范 | 适合团队共同开发和维护 |
