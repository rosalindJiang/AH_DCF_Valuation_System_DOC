# 06 批量运行与调度设计

## 1. 调度目标

系统需要支持全市场批量估值和局部样本测试。调度模块用于保证任务能够按照固定频率自动运行，并在失败时记录日志和异常信息。

## 2. 运行模式

| 模式 | 说明 |
|---|---|
| sample_test | 样本股票测试，用于调试数据流程 |
| single_stock | 单只股票估值，用于投研分析 |
| market_batch | 全市场批量估值 |
| incremental_update | 增量更新最新行情和财务数据 |
| revaluation | 使用新参数重新计算历史估值 |

## 3. 推荐调度频率

| 任务 | 频率 |
|---|---|
| 股票基础信息更新 | 每周 |
| 行情数据更新 | 每个交易日收盘后 |
| 财务报表更新 | 每日检查，公告期重点更新 |
| DCF 批量估值 | 每周或每月 |
| 数据质量报告 | 每次估值任务后 |
| 参数版本归档 | 每次参数变更后 |

## 4. 任务执行流程

```text
读取配置
   ↓
生成任务 ID
   ↓
检查数据库连接和数据源状态
   ↓
采集或更新数据
   ↓
执行数据质量检查
   ↓
运行 DCF 估值
   ↓
写入估值结果
   ↓
生成运行报告
   ↓
记录任务状态
```

## 5. 异常处理机制

| 异常 | 处理方式 |
|---|---|
| 数据源接口失败 | 记录失败接口，允许重试，必要时切换备用数据源 |
| 单只股票财务数据缺失 | 跳过该股票，写入异常清单 |
| WACC <= 终端增长率 | 停止该股票估值，标记模型参数异常 |
| 股本缺失或为 0 | 停止每股价值计算，进入异常清单 |
| 内在价值极端异常 | 保留结果但标记为需人工复核 |

## 6. 日志设计

每次任务需要记录：

- job_id；
- job_type；
- start_time；
- end_time；
- status；
- total_stocks；
- success_count；
- failed_count；
- warning_count；
- config_version；
- parameter_version；
- error_message。

## 7. 最小可运行版本建议

虽然本考试不要求提交具体代码，若后续实现系统，建议最小版本先支持：

- 3 只 A 股；
- 2 只 H 股；
- SQLite 本地数据库；
- 手动运行；
- 输出一张估值结果表；
- 所有参数从 YAML 配置文件读取。
